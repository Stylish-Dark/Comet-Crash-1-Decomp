# PROJECT PLAN

## End state

A reproducible Windows-native Comet Crash port that:
- is built from the user's legally obtained NPEB00142 v1.00 game data;
- ships no proprietary game binaries/assets;
- preserves original gameplay and controller behaviour;
- boots and plays missions reliably;
- supports practical PC controls and display options;
- can be rebuilt from a fresh checkout using the pinned toolchain and documented pipeline.

## Architecture

1. **Guest-code layer**
   - Recompiled PPU code generated by ps3recomp.
   - Lifted SPU workloads registered by content fingerprint.

2. **PS3 compatibility layer**
   - Pinned ps3recomp runtime/HLE.
   - Deterministic Comet-specific runtime patches and compatibility overrides.

3. **PC adaptation layer**
   - Windows D3D12 presentation.
   - Filesystem/title-path mapping.
   - Controller preservation.
   - Mouse/keyboard adaptation.
   - Host settings and overlay.

4. **Build/reproducibility layer**
   - Strict game/version/hash validation.
   - Analysis baseline checks.
   - PPU/SPU/HLE completeness gates.
   - Exact upstream pin verification.
   - Clean generated/build-state handling.
   - CI scaffold compilation with the real pinned PPU lifter.

5. **Diagnostics layer**
   - Durable text boot logging plus machine-readable summary sidecar.
   - Stage markers and first-frame outcome tracking.
   - Provenance binding to the exact port/toolchain build.
   - Native crash context and capped hang watchdog snapshots.
   - Conservative subsystem triage that distinguishes chronological symptoms from later specific evidence.
   - Durable timeout/Ctrl+C termination paths.

## Phases

### Phase 1 — Reproducible source-title analysis
Status: **complete**.

Validate the title, reconstruct the ELF locally, reproduce PPU/import/SPU analysis, and reject analysis drift.

### Phase 2 — Reproducible static lift/build
Status: **complete for pre-boot gating**.

Lift PPU/SPU code, apply narrowly scoped compatibility fixes, reject unsupported reachable code or unresolved HLE coverage, build the Windows runner against the exact pinned runtime.

### Phase 3 — First native Windows boot
Status: **current**.

Run against real user-owned game data, capture the first concrete runtime blocker, and iterate one evidenced failure at a time until visible output is stable.

### Phase 4 — Playable vanilla game
Status: **not started**.

Verify missions, simulation, input, pause/exit, save/load, audio and clean shutdown against the PS3/RPCS3 behavioural baseline.

### Phase 5 — Native PC input
Status: **partially implemented**.

Compatibility-mode mouse/controller coexistence is already present. Direct absolute mouse/world-pointer mapping and broader keyboard bindings wait until vanilla gameplay is stable.

### Phase 6 — PC polish
Status: **deferred**.

Resolution/display polish, safe aspect-ratio work, frame pacing/high refresh, packaging and user-facing diagnostics. Any frame-rate change must avoid changing gameplay simulation speed.

## Engineering constraints

- Never commit/distribute Comet Crash binaries, assets, PKG/RAP/RIF, decrypted EBOOT/ELF, extracted proprietary SPU images, or non-redistributable Sony SDK material.
- Do not fake core gameplay behaviour in host code to obtain a boot.
- Optional PS3 online/media services must fail explicitly or use intentional offline-safe semantics rather than fabricated success.
- Preserve vanilla/controller behaviour before PC refinements.
- SPU work is evidence-driven.
- Toolchain drift is a hard stop until reviewed.
- Runtime fixes are driven by observed boot/gameplay evidence.
- Every substantial work cycle must checkpoint source plus `STATE.md`, `WORK_QUEUE.md` and `SESSION_LOG.md` before the execution window becomes risky.

## Verification strategy

- Python unit/regression tests for pipeline, patchers, validation and audits.
- `compileall` for Python syntax.
- Repository-safety gate for proprietary-material exclusion.
- Linux and Windows unit/`compileall` gates plus repository safety.
- Windows CI compile/link against exact pinned ps3recomp and real pinned PPU lifter output from a non-proprietary fixture.
- Real Windows boot logs for runtime progress.
- Behavioural comparison with PS3/RPCS3 once gameplay is reachable.
